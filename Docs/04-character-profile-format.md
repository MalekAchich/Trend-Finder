# 04: Character Profile Format

**Status:** Draft v1

Characters live **outside the app**, in `AI Influencers Characters/` at the project root (configured via `CHARACTERS_DIR`). The folder is the source of truth; the app imports it and re-syncs on change. Taste profiles and stats generated by the app live in the database, not in this folder.

## Folder layout

```
AI Influencers Characters/
└── <Name>/
    ├── profile.md              # required, format below
    ├── <Name>.png              # canonical image (identity anchor), required
    ├── *.png / *.jpg           # reference sheets (body views, face views, outfits)
    └── seeds/                  # optional: seed video files or seeds.txt with one URL per line
```

## `profile.md`

YAML front matter for the machine-readable fields, then Markdown sections the agents read verbatim.

```markdown
---
name: Nicolaiz
slug: nicolaiz
status: active                      # active | paused
canonical_image: Nicolaiz.png
reference_images: [Nicolaiz body views.png, Nicolaiz face views.png]
language: en
target_regions: []                  # e.g. [US, GB]; used for trend filters
platforms: [tiktok, instagram, youtube_shorts]
socials:                            # the character's own accounts (for insights; never used for scraping)
  tiktok: null
  instagram: null
  youtube: null
---

## Persona            (who they are, in 3–6 lines)
## Energy & charisma  (how they move and react; what makes them watchable)
## Comedic engine     (where the humor comes from)
## Niche / context    (the settings and topics they own)
## Look (fixed)       (identity traits that must never change)
## Kling constraints  (what the production model can and can't do with this character)
## Do / Don't         (content rules)
## Inspiration        (reference creators and how this character differs from them)
```

## Rules

- The **canonical image** is the only identity reference for scoring and briefs. Reference sheets are supporting material.
- Agents receive a **compact character brief** (front matter + sections, about 600 tokens) plus the canonical image. They don't see every reference sheet unless a task needs them.
- Changing `profile.md` creates a new **character version** in the database. Findings record which version they were scored against.
